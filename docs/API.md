# API reference

Base URL: `/api`, same origin as the client. In production that is
`https://tourney-host.vercel.app/api`; in development Vite proxies `/api` to
`http://localhost:2000`.

This document is written against the route definitions and the zod schemas in
`server/src/modules/*`. Those files are the source of truth — if the two ever
disagree, the schema is right and this file is stale.

---

## Conventions

**Authentication** is a JWT in an `httpOnly` cookie named `token`, set by
`POST /api/auth/login` and `POST /api/auth/signup`. It is `SameSite=Lax`,
`Secure` in production, and scoped to `/`. There is no bearer-token path and no
token in `localStorage`; send credentials with the request
(`fetch(..., { credentials: 'include' })` — the client's API layer already
does).

Each endpoint below is marked:

|              |                                                                           |
| ------------ | ------------------------------------------------------------------------- |
| **public**   | works signed out                                                          |
| **optional** | works signed out, but returns extra viewer-specific fields when signed in |
| **auth**     | 401 without a valid cookie                                                |
| **host**     | 403 unless the caller hosts that tournament                               |
| **admin**    | 403 unless the account's role is `admin`                                  |

**Validation.** Every `params`, `query`, and `body` is parsed by zod _before_
the controller runs. A failure is a `400` with `code: "VALIDATION_FAILED"` and
a `details` array of `{ path, message }`.

**Errors** all have one shape:

```json
{ "error": { "message": "…", "code": "…", "details": [] } }
```

`code` and `details` are optional. Codes in use: `VALIDATION_FAILED`,
`INVALID_ID`, `INVALID_JSON`, `DUPLICATE`, `RATE_LIMITED`, `INTERNAL_ERROR`,
`DATABASE_UNAVAILABLE`, `CRON_NOT_CONFIGURED`, `NO_ROUTE`.

Common statuses: `400` validation, or a rule the tournament's current state
forbids ("this has already started"); `401` not signed in, or bad credentials;
`403` signed in but not allowed; `404` no such resource; `409` a uniqueness
conflict — a taken email or username; `429` rate limited; `500` a bug; `503`
the database is unreachable.

**Ids** are UUID v4 strings, generated by the application rather than exposing
Mongo's `ObjectId`. Anything documented as an id is a UUID.

**Rate limits.** `/api/auth/signup` and `/api/auth/login`: 20 per 15 minutes per
address. `/api/credits/checkout/*`: 5 per hour per account. `/api/cron/*`: 10
per hour. Limits are enforced in production only.

## Health

### `GET /api/health` — public

Liveness and database readiness. Connects best-effort, so a cold serverless
container still reports honestly.

```json
{ "status": "ok", "database": "connected" }
```

`status` is `"ok"` or `"degraded"`; `database` is `connected`, `connecting`,
`disconnecting`, or `disconnected`. Always `200`.

## Auth

### `POST /api/auth/signup` — public

```json
{ "email": "you@example.com", "username": "you", "password": "Passw0rdy" }
```

- `email` — valid address, trimmed and lowercased.
- `username` — 3–24 characters, `[a-zA-Z0-9_.-]` only.
- `password` — 8–128 characters, and must contain a lowercase letter, an
  uppercase letter, and a digit.

`201` with `{ user }` and the auth cookie set. `409 DUPLICATE` if the email or
username is taken.

### `POST /api/auth/login` — public

```json
{ "email": "demo@tourney.app", "password": "…", "rememberMe": false }
```

`200` with `{ user }` and the cookie. `rememberMe` extends the cookie's life
from one day to thirty.

`401` for both a wrong password and an unknown email, with the same message —
telling the two apart would be a free account-enumeration oracle.

### `POST /api/auth/logout` — public

Clears the cookie. `204`, no body. Safe to call when already signed out.

## Users

### `GET /api/users/me` — auth

`200 { user }`, where `user` is `{ id, username, email, credits, isHost, isAdmin }`.
`401` when signed out — which is normal, and is how the client decides whether
to render a signed-in shell.

### `GET /api/users/me/transactions` — auth

| Query   |               |            |
| ------- | ------------- | ---------- |
| `limit` | integer 1–100 | default 50 |

`200 { transactions }`, newest first. Each row is
`{ _id, userId, type, amount, description, createdAt }` where `type` is one of
`purchase`, `entry_fee`, `bank_deposit`, `payout`, `host_upgrade`, `refund`, and
`amount` is the signed change to that account's balance.

### `POST /api/users/me/become-host` — auth

Charges `HOST_UPGRADE_COST` (20 credits) once and sets `isHost`. In a
transaction, with a ledger row. `200 { user }`.

`400` if already a host, or if the balance is short.

## Tournaments

### `GET /api/tournaments` — public

The catalogue.

| Query                        |                                  |                               |
| ---------------------------- | -------------------------------- | ----------------------------- |
| `page`                       | integer ≥ 1                      | default 1                     |
| `limit`                      | integer 1–50                     | default 12                    |
| `search`                     | string ≤ 120 chars               | matches title and description |
| `category`                   | one of the 13 category slugs     |                               |
| `type`                       | `brackets` \| `battle royale`    |                               |
| `accessibility`              | `open` \| `application required` |                               |
| `status`                     | `upcoming` \| `live` \| `ended`  |                               |
| `minEntryFee`, `maxEntryFee` | integer ≥ 0                      |                               |

```json
{
  "tournaments": [ … ],
  "pagination": { "page": 1, "limit": 12, "total": 10, "pages": 1 }
}
```

Omitted filters are omitted, not sent as empty strings.

### `GET /api/tournaments/trending` — public

| Query   |              |            |
| ------- | ------------ | ---------- |
| `limit` | integer 1–24 | default 10 |

Open tournaments with the most entrants. `200 { tournaments }`.

### `GET /api/tournaments/categories` — public

`200 { categories }` — the fixed list of `{ slug, name }`. Free text was
deliberately not used, so filtering, seeding, and the category artwork all agree
on one set.

### `GET /api/tournaments/mine` — auth

Everything the caller hosts or competes in. `200 { tournaments }`.

### `GET /api/tournaments/:tournamentId` — optional

The full tournament: participants, matches, prizes, updates, contact info, and
a `viewer` object — `{ isHost, isJoined, hasApplied, isAccepted }` — computed by
the server. The client never infers those from the participant list.

`404` if there is no such tournament.

### `POST /api/tournaments` — auth, host

The body is a discriminated union on `type`.

Shared fields:

|                        |                                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `title`                | 3–80 characters                                                                                                      |
| `category`             | a category slug                                                                                                      |
| `accessibility`        | `open` \| `application required`                                                                                     |
| `teamSize`             | integer 1–16; `1` is a solo tournament                                                                               |
| `entryFee`             | integer 0–1,000,000                                                                                                  |
| `description`, `rules` | HTML, sanitised server-side. Limits are on the _visible_ text — 200 and 800 characters — not the markup              |
| `contactInfo`          | `{ email?, phone?, socialMedia? { discord?, instagram?, twitter?, facebook? } }`, strict — unknown keys are an error |
| `applicationForm`      | up to 10 question labels, at most 80 characters each; **required** when `accessibility` is `application required`    |
| `startDate`, `endDate` | dates; the end must be after the start                                                                               |

`type: "brackets"` adds `maxCapacity` (a **power of two**, 2–256 — a single
elimination bracket cannot pair an odd round) and `prize`.

`type: "battle royale"` adds `maxCapacity` (2–1000) and `prizes`, an array of
`{ rank, prize }` — at least one, each rank at most once, and no rank beyond the
capacity.

`201 { tournament }`. `403` if the account is not a host.

### `PATCH /api/tournaments/:tournamentId` — host

Only `title`, `description`, `rules`, `contactInfo`, `startDate`, `endDate`.
Strict: any other key is a `400`. Format, capacity, and prizes are deliberately
immutable once the tournament exists, because entrants signed up on the strength
of them.

`400` once the tournament has started.

### `DELETE /api/tournaments/:tournamentId` — host

Cancels it and, in one transaction, refunds every entry fee to whoever paid it
and returns the remaining bank — the host's own top-up — to the host. So a
cancelled tournament leaves the same number of credits in the world as it found.

`400` once it has started: at that point the result is what the prizes are for.

### `POST /api/tournaments/:tournamentId/updates` — host

`{ "content": "Round one starts in ten minutes." }` — 1–500 characters.
`200 { tournament }`.

### Entering

#### `POST /api/tournaments/:tournamentId/join/solo` — auth

Moves `entryFee` from the caller's wallet into the tournament bank and adds them
as a participant. Transactional, with a ledger row.

`400` if the tournament is full, already started, team-based,
application-gated, already joined, or the balance is short.

#### `POST /api/tournaments/:tournamentId/join/team` — auth

`{ "teamId": "…" }`. The **team leader** pays the entry fee for the whole team.
The team's size must equal the tournament's `teamSize`.

`403` if the caller does not lead that team.

#### `POST /api/tournaments/:tournamentId/applications` — auth

```json
{ "teamId": "…", "fields": [{ "label": "Your rank?", "input": "Gold" }] }
```

Every question must be answered. `teamId` only for a team tournament. No credits
move — the entry fee is charged when the accepted applicant takes their slot.

---

### Host controls

#### `GET /api/tournaments/:tournamentId/manage` — host

The management view: everything the public endpoint returns, plus applications
and the bank's state.

#### `POST /api/tournaments/:tournamentId/applications/:applicationId/accept` — host

#### `POST /api/tournaments/:tournamentId/applications/:applicationId/reject` — host

Accepting marks the applicant accepted; they then join and pay like anyone else.

#### `POST /api/tournaments/:tournamentId/bank/deposit` — host

`{ "amount": 150 }` — a positive integer. Moves credits from the host's wallet
into the tournament bank. The deposit is `min(amount, shortfall)`, so a host
cannot over-fund a bank by fat-fingering a zero. `400` if the bank is already
full.

`200 { deposited, bank, required }`.

#### `POST /api/tournaments/:tournamentId/shuffle` — host

Reseeds the bracket order. `400` once started.

#### `POST /api/tournaments/:tournamentId/start` — host

The gate the whole economy rests on. `400` unless **the bank covers the
advertised prize total**, and:

- a **bracket** has every slot filled — a single-elimination draw cannot pair a
  half-empty field;
- a **battle royale** has at least two entrants.

#### `PATCH /api/tournaments/:tournamentId/matches` — host

`{ "matches": ["<winner uuid>", null, …] }` — one entry per match in bracket
order, `null` where the result is not in yet. Winners advance automatically.

#### `PATCH /api/tournaments/:tournamentId/participants` — host

`{ "participants": [{ "id": "…", "score": 42, "eliminated": false }] }` — the
battle-royale scoreboard. Team entries may carry per-member rows.

#### `POST /api/tournaments/:tournamentId/end` — host

Ends it and pays out from the bank: the bracket winner, or the ranked prize
table. One transaction, one ledger row per payout. `400` if a bracket's final
has no recorded winner yet.

## Teams

All team routes require auth.

|                                               |                                                                    |
| --------------------------------------------- | ------------------------------------------------------------------ |
| `GET /api/teams/mine`                         | Teams the caller belongs to                                        |
| `GET /api/teams/:teamId`                      | One team, with its roster and join code                            |
| `GET /api/teams/code/:code`                   | Look a team up by its 6-character code, before joining             |
| `POST /api/teams`                             | `{ "name": "Night Owls" }` — 3–32 characters. The creator leads it |
| `POST /api/teams/join/:code`                  | Join by code                                                       |
| `POST /api/teams/:teamId/leave`               | Leave. `400` while the team is competing                           |
| `DELETE /api/teams/:teamId`                   | Leader only. `400` while competing                                 |
| `PATCH /api/teams/:teamId/leader`             | `{ "username": "…" }` — hand leadership over                       |
| `DELETE /api/teams/:teamId/members/:username` | Leader only                                                        |

Join codes are exactly six characters, `[A-Z0-9]`, and are uppercased on the way
in — so a code read off a screen works whatever case it is typed in.

## Credits

### `GET /api/products` — public

### `GET /api/products/:productId` — public

The credit packages. Public, so a guest can see what credits cost before signing
up. `404` for an unknown id.

### `POST /api/credits/checkout/:productId` — auth, rate limited

**The demo checkout.** No payment is processed and no card details are accepted
— the request body carries only the package id, which is in the URL. The card
fields in the UI are a mock-up that never leaves the browser, and
`npm run check:regressions` has a gate that fails the build if they ever do.

Grants the package's credits in a transaction, with a `purchase` ledger row.

```json
{ "demo": true, "granted": 100, "product": { … }, "user": { … } }
```

`429` after 5 in an hour — the cap is per account rather than per address,
because credits are free money here.

## Cron

### `GET /api/cron/reseed` — bearer token

### `POST /api/cron/reseed`

Wipes and rebuilds the demo dataset. Scheduled daily at 04:00 UTC by Vercel
Cron, which is why an operation this destructive answers a `GET` — that is the
only method Vercel Cron issues.

Requires `Authorization: Bearer $CRON_SECRET`, compared in constant time.

- `503 CRON_NOT_CONFIGURED` when `CRON_SECRET` is unset. The route does not run
  at all rather than running unauthenticated.
- `401` for a missing, malformed, or wrong token.

```json
{
  "ok": true,
  "cleared": { "tournaments": 10, "teams": 4, "users": 13, "transactions": 35 },
  "seeded": { "users": 14, "teams": 4, "products": 0, "tournaments": 10 },
  "durationMs": 4030
}
```

See [DEPLOYMENT.md](DEPLOYMENT.md#the-scheduled-reseed) for how it is guarded and
what it measures.
